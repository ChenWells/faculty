# 房東管理系統設計文檔

## 1. 系統架構概述

### 1.1 總體架構
房東管理系統採用現代化的三層架構設計：
- **前端層**：使用React/Next.js構建的響應式Web應用
- **API服務層**：Node.js + Express實現的RESTful API
- **資料存儲層**：Google Sheets + PostgreSQL關聯式資料庫

系統將採用微服務架構，主要分為以下幾個服務：
- 身份認證服務
- 租客管理服務
- 合約管理服務
- 費用計算服務
- 電費計算服務
- 通知服務
- 收租管理服務

## 2. 功能需求描述

### 2.1 電費計算模組

#### 2.1.1 電費計算方式
系統支援三種電費計算方式：

**方式一：固定電價**
- 每度電固定價格（例：每度電5元）
- 計算公式：電費 = 總用電度數 × 固定單價

**方式二：平均電價（私電+公電）**
- 根據前期電費計算平均每度電費
- 計算公式：電費 = (私電度數 + 公電度數) × 平均每度電費
- 平均每度電費 = 前期總電費 ÷ 前期總用電度數

**方式三：混合電價**
- 私電使用平均電價，公電使用固定電價
- 計算公式：電費 = 私電度數 × 平均每度電費 + 公電度數 × 固定每度電費

#### 2.1.2 電費計算功能
- **輸入電表度數**：支援手動輸入或拍照識別電表度數
- **自動計算電費**：根據選擇的計算方式自動計算電費
- **歷史電費查詢**：查看前期電費記錄和計算歷史
- **電費統計分析**：提供用電趨勢分析和費用統計

### 2.2 合約管理模組

#### 2.2.1 合約建立
合約必須包含以下資訊：
- **基本資訊**：合約編號、簽約日期、起訖日期
- **租金設定**：月租金金額、押金金額
- **電費計算方式**：選擇上述三種計算方式之一
- **其他費用**：管理費、清潔費、網路費等
- **付款條件**：付款日期、付款方式、逾期罰則

#### 2.2.2 合約管理功能
- **合約CRUD操作**：建立、查詢、修改、終止合約
- **合約狀態追蹤**：有效、到期、終止等狀態管理
- **合約範本管理**：提供標準合約範本

### 2.3 費用計算與收租管理模組

#### 2.3.1 月度費用計算
- **自動計算**：租金 + 電費 + 其他費用 = 本月應收費用
- **費用明細**：提供詳細的費用分解說明
- **費用調整**：支援手動調整費用項目

#### 2.3.2 收租流程管理
- **收租通知**：透過LINE自動發送收租通知
- **繳費記錄**：記錄房客繳費情況
- **繳費確認**：房客繳費後自動發送確認通知到LINE群組
- **逾期管理**：逾期提醒和罰金計算

### 2.4 通知服務模組

#### 2.4.1 LINE通知功能
- **收租通知**：每月自動發送收租通知
- **繳費確認**：收到租金後發送確認通知
- **逾期提醒**：逾期未繳費的提醒通知
- **系統通知**：重要系統事件通知

#### 2.4.2 通知設定
- **通知時機**：可設定通知發送的時間和頻率
- **通知內容**：可自訂通知內容模板
- **群組管理**：管理LINE群組和通知對象

### 2.5 用戶權限管理模組

#### 2.5.1 多管理者支援
- **管理者角色**：支援1到多位房屋管理者
- **權限平等**：所有管理者具有相同權限
- **操作記錄**：記錄所有管理者的操作歷史
- **協作功能**：管理者間的協作和溝通

#### 2.5.2 權限控制
- **功能權限**：合約管理、費用計算、收租管理等
- **資料權限**：房屋資料、租客資料、財務資料等
- **操作權限**：查看、新增、修改、刪除等

### 2.6 資料存儲模組

#### 2.6.1 Google Sheets整合
- **自動同步**：系統資料自動同步到Google Sheets
- **資料備份**：重要資料自動備份到Google Sheets
- **報表匯出**：支援將資料匯出為Google Sheets格式
- **離線存取**：透過Google Sheets提供離線資料存取

#### 2.6.2 資料安全
- **存取控制**：Google Sheets的存取權限管理
- **資料加密**：敏感資料的加密存儲
- **備份策略**：定期備份和災難恢復

## 3. 模組設計

### 3.1 用戶認證模組
- **功能**：處理用戶註冊、登入、權限管理
- **技術**：Google OAuth 2.0、JWT
- **角色設計**：
  - 管理者（房東）：完整系統存取權
  - 租客：僅查看權限
- **認證流程**：
  - 使用Google帳號登入
  - 自動授權Google Sheets和Drive存取
  - 支援多管理者協作

### 3.2 租客管理模組
- **功能**：處理租客資料的CRUD操作
- **主要實體**：
  - 租客基本資訊
  - 聯絡方式
  - 緊急聯絡人
- **特殊功能**：資料匯出、資料驗證

### 3.3 房屋管理模組
- **功能**：管理房屋基本資訊和狀態
- **主要實體**：
  - 房屋基本資訊
  - 房屋設施
  - 房屋狀態
- **特殊功能**：房屋照片管理、設施清單

### 3.4 財務管理模組
- **功能**：管理所有財務相關操作
- **主要實體**：
  - 收入記錄
  - 支出記錄
  - 財務報表
- **特殊功能**：財務分析、稅務計算

## 4. 技術規格

### 4.1 前端技術
- **框架**：React 18 + Next.js 14
- **UI庫**：Material-UI 或 Ant Design
- **狀態管理**：Redux Toolkit 或 Zustand
- **表單處理**：React Hook Form
- **圖表**：Chart.js 或 Recharts

### 4.2 後端技術
- **框架**：Node.js + Express.js
- **資料庫**：PostgreSQL
- **ORM**：Prisma 或 Sequelize
- **認證**：Google OAuth 2.0
- **API文檔**：Swagger/OpenAPI

### 4.3 第三方服務
- **認證服務**：Google OAuth 2.0
- **通知服務**：LINE Messaging API
- **資料存儲**：Google Sheets API
- **文件存儲**：Google Drive API
- **部署**：Vercel (前端) + Railway (後端)

## 5. 資料庫設計

### 5.1 核心資料表
- **users**：用戶資料
- **properties**：房屋資料
- **tenants**：租客資料
- **contracts**：合約資料
- **electricity_records**：電費記錄
- **payment_records**：收租記錄
- **notifications**：通知記錄

### 5.2 關聯關係
- 一個房屋可以有多個合約（歷史）
- 一個合約對應一個租客
- 一個合約可以有多個電費記錄
- 一個合約可以有多個收租記錄

## 6. 系統流程

### 6.1 收租流程
1. 系統自動計算月度費用
2. 發送LINE收租通知
3. 租客繳費
4. 記錄繳費情況
5. 發送繳費確認通知
6. 更新財務記錄

### 6.2 電費計算流程
1. 輸入電表度數
2. 選擇計算方式
3. 系統自動計算電費
4. 更新費用記錄
5. 同步到Google Sheets

## 7. 安全性考量

### 7.1 資料安全
- 所有敏感資料加密存儲
- 使用HTTPS進行資料傳輸
- 定期資料備份

### 7.2 存取控制
- 基於角色的存取控制
- 多因素認證
- 操作日誌記錄

## 8. 效能考量

### 8.1 系統效能
- 支援同時100個用戶在線
- 頁面載入時間 < 3秒
- API響應時間 < 1秒

### 8.2 擴展性
- 微服務架構支援水平擴展
- 資料庫分片支援大量資料
- 快取機制提升效能
